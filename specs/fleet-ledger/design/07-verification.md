# L6 — 검증 (게이트 · 가드 · 변이 · 추적성 집행)

`Satisfies: REQ-701, REQ-702, REQ-703, REQ-704 + 모든 REQ (추적성)`

---

## 1. 게이트의 정의

```
   make check  =  ruff check  +  ruff format --check  +  mypy  +  pytest
```

**조건 두 개가 게이트를 게이트로 만든다:**

1. **오프라인** — 네트워크 없이 통과한다(REQ-701). 어떤 과금 API도 부르지 않는다.
2. **결정론적** — 시각·난수·외부 상태에 의존하지 않는다(REQ-702).

⚠️ **이 둘이 무인 실행(overnight harness)의 안전 조건이다.** 게이트가 과금하면 밤새 도는
루프가 밤새 돈을 쓴다. 레퍼런스 저장소에서 게이트가 테스트마다 모델을 호출해 **288초**가
걸렸고, 고치자 **39초**가 됐다 — **그때 깨진 테스트는 0건이었다.** 아무도 모르고 있었다.

## 2. ⚠️ 초록에 붙는 조건 — 레퍼런스가 값을 치르고 배운 것

게이트가 초록이어도 다음이면 그 초록은 주장이 아니다:

| 조건 | 무엇이 일어나나 | 우리의 대응 |
|---|---|---|
| **시간** | 픽스처가 절대 시각을 하드코딩하면 통과는 달력이 움직이기 전까지만 참 | `FrozenClock` 포트(REQ-702) |
| **환경** | 선언 안 된 패키지 위에서 통과 — 새 클론은 아무도 못 통과 | `pyproject.toml`에 전부 선언 + CI가 새 클론에서 돈다 |
| **하중** | 행복 경로만 태운 가드는 안전망을 지워도 초록 | **모든 가드는 지워 보고 red 확인**(§4) |
| **skip** | skip은 실패가 아니라서, 검사 안 하는 게이트와 통과한 게이트가 같은 색 | **게이트 숫자에 날짜와 잰 기계를 붙인다** |
| **관측 지점** | 독자가 읽지 않는 물건에 대고 물으면 결함을 그림자로 센다 | 가드는 **응답/저장소**에 묻는다 |
| **가드 자신** | 기본값과 같은 값을 고른 픽스처는 가드가 아니다 | 픽스처 값은 **기본값과 다르게** 고른다 |

## 3. 가드 7종

각 가드는 **하나의 불변식**을 지킨다(`design.md` §5).

| id | 지키는 것 | 관측 지점 | 변이(지웠을 때 red를 확인할 대상) |
|---|---|---|---|
| **G1** | `DENY`면 실행기 **호출 0** (I-2 · REQ-303) | `RecordingExecutor.call_count` | 게이트를 자문(advisory)으로 바꾼다 |
| **G2** | `assumed` 불변 (I-1 · REQ-204) | 화해 후 `entry.assumed` | 화해가 `assumed`를 덮게 한다 |
| **G3** | `method ↔ verifiability` 일관 (I-3 · REQ-203) | 저장된 항목 전수 | 매핑 표에 잘못된 짝을 넣는다 |
| **G4** | 모든 항목에 `budget_decision` (I-4 · REQ-301) | 저장된 항목 전수 | 게이트 우회 경로를 만든다 |
| **G5** | 게이트 중 라이브 어댑터 생성 0 (I-6 · REQ-701) | 어댑터 팩토리 카운터 | 테스트에 라이브 클라이언트를 주입한다 |
| **G6** | ★ **모든 REQ가 테스트에 참조된다** (추적성) | `requirements.md` 파싱 | REQ를 하나 추가하고 테스트를 안 만든다 |
| **G7** | 액션 1회 = 원장 1행 (I-5 · REQ-201) | 재시도 시나리오 후 항목 수 | 재시도가 같은 id를 덮게 한다 |

### 3.1 ★ G6 — 이것이 spec-driven과 spec-decorated를 가른다

```python
def test_g6_every_requirement_is_referenced_by_a_test():
    req_ids = parse_requirement_ids(SPEC / "requirements.md")   # REQ-\d{3}
    referenced = scan_test_names_and_docstrings(TESTS)
    missing = req_ids - referenced - DROPPED
    assert not missing, f"요구사항에 대응하는 테스트가 없다: {sorted(missing)}"
```

**공허 통과 방지**: `assert len(req_ids) >= 30` — 파서가 망가져 0개를 읽으면
`missing`이 공집합이 되어 **조용히 통과**한다. 레퍼런스에서 실제로 난 실패 방식이다.

**`DROPPED` 집합**: 폐기된 REQ는 목록이 아니라 **`requirements.md`의 상태 표기에서 유도**한다.
손으로 관리하는 면제 목록은 낡는다. ⚠️ **면제는 목록이 아니라 경계여야 한다.**

### 3.2 G6의 형제 검사 — 세는 순간 전부 센다
G6는 테스트 커버리지만 보면 절반이다. 같은 스캔에서 **세 가지를 함께** 확인한다:

1. 모든 REQ가 **테스트**에 참조되는가
2. 모든 REQ가 **`tasks.md`의 어떤 태스크**에 참조되는가 (구현 계획 없는 요구사항 = 구멍)
3. 모든 REQ가 **어떤 설계 문서의 `Satisfies:`**에 있는가
   (⚠️ 귀속처가 `design/` 밖일 수 있다 — 예: REQ-802의 설계는 `docs/REFERENCE_FROM_PARENT.md`다.
   스캔 범위를 `design/`으로 좁히면 **고아를 거짓으로 보고한다**)

⚠️ **①만 검사하는 G6는 절반만 묻는 가드다** — 레퍼런스 저장소에서 반복해 난 실패 형태다(#10).

## 4. 변이 검증 — 가드를 가드로 인정하는 절차

**규칙: 지워 보고 red가 나오지 않은 가드는 가드가 아니다.**

```
   scripts/mutate.sh <mutation-id>
     ① 기준선: make check → 통과 수를 기록한다
     ② 변이 적용
     ③ make check → red인가? 몇 건이 죽었는가?
     ④ 복구 (같은 스크립트 안에서)
     ⑤ make check → 초록으로 돌아왔는가?  ← 이게 안 되면 복구가 아니다
     ⑥ git diff --stat 이 비었는가?
```

⚠️ **레퍼런스가 변이 하네스 자신에서 다섯 번 틀렸다:**
- **틀린 테스트 파일**에 물어 "가드 없음"으로 읽었는데 전체 스위트로는 red였다
- **문법을 깬 변이**를 red로 셌다 (컴파일 실패는 검증이 아니다)
- **없는 파일**을 적어 `no tests ran`을 red로 셌다
- 복구가 `git checkout --`이라 **커밋 안 된 고침을 날렸다**

⇒ **변이·실행·복구는 한 스크립트 안에.** 그리고 **복구는 프로세스 밖에도**(디스크 백업).
⇒ **결과를 적을 때 "어디에 물었는지"까지 적는다.**

## 5. 테스트 계층

| 계층 | 무엇 | 어댑터 | 게이트에 포함 |
|---|---|---|---|
| 단위 | 비용 계산 · 판정 행렬 · delta | 전부 fake | ✅ |
| 계약 | 포트 구현이 프로토콜을 만족 | fake + 실제(선택) | ✅ (fake만) |
| 통합(오프라인) | execute → 게이트 → 원장 전체 경로 | 전부 fake | ✅ |
| 라이브 | Vertex·Firestore·BQ 실물 | 실제 | ❌ **별도 타깃** `make live-check` |

⚠️ **라이브 테스트는 게이트에 넣지 않는다**(REQ-701). 대신 **손으로 돌리고 증거를 남긴다** —
`docs/evidence/`에 날짜와 명령과 출력. **"한때 통과했다"와 "지금 재현된다"는 다르다.**

## 6. ⚠️ 스텁이 만드는 거짓 초록

`FakeModel`은 REQ-501을 만족시키지 **못한다.** 스텁 위에서 통과하는 테스트는
*"우리 코드가 이 인터페이스를 이렇게 부른다"*를 말할 뿐, *"그 인터페이스가 존재한다"*를
말하지 않는다.

레퍼런스에서 정확히 이 사고가 있었다 — 테스트가 SDK 모듈을 스텁해 통과했는데
**그 클래스는 실제 라이브러리에 없었다.** 진짜 라이브러리에 대고 한 번도 실행된 적이 없었다.

⇒ **REQ-501·REQ-502의 수용 기준은 실물 호출과 실물 배포다.** T2가 그것이고,
그 증거는 게이트가 아니라 `docs/evidence/`에 남는다.

## 7. 게이트 숫자 기록 규약

진행 기록에 통과 수를 적을 때는 **날짜와 잰 기계**를 함께 적는다.

> `make check` → **N passed** (2026-08-2X 로컬 macOS·py3.13, Ns)

⚠️ 숫자만 적으면 다른 환경의 숫자와 비교돼 거짓 증가/감소를 만든다.
그리고 **여러 문서에 같은 숫자를 복제하지 않는다** — 복제본은 한쪽만 낡는다.
