# L8 — 실증 최적화 · 4분 영상

`Satisfies: REQ-703, REQ-704, REQ-601, REQ-801`

---

## 1. 원칙 — 프로덕션 코드와 실증 코드는 다른 것을 최적화한다

이 프로젝트는 후자다. 심사 배점이 **Demo & Production Readiness 30%**이고,
Innovation 40%조차 **4분 안에 전달돼야** 점수가 된다.

| # | 원칙 | 이 프로젝트에서 |
|---|---|---|
| 1 | **결정론적 데모** | `make demo` 한 줄. 랜덤·외부 의존 금지 |
| 2 | **타이머를 줄인다** | 화해 대기·예산 창을 영상 길이에 맞춘다. **상수 한 곳**(REQ-704) |
| 3 | **실패 경로를 1급으로** | **거부 장면이 없으면 이 데모는 실패다**(§3 비트 3) |
| 4 | **화면에 보이게** | 판정 근거가 응답에 있다(REQ-601). 로그에만 있으면 없는 것 |
| 5 | ⚠️ **그렇다고 가짜로 만들지 않는다** | 타이머 단축은 최적화, **결과 하드코딩은 실증이 아니다** |

⚠️ **원칙 5의 구체적 함정**: 화해가 하루 걸리므로 데모에서 기다릴 수 없다. **유혹은
`measured`를 미리 박아 두는 것**이다. 그러면 데모가 증명하는 게 없다.
⇒ **정직한 해법**: 전날 실제로 실행한 액션의 진짜 청구 데이터를 **당일 화해**한다.
즉 **데모 전날 액션을 돌려 둔다.** 영상은 "어제 이 액션을 돌렸고, 오늘 청구서가 도착했다"를
보여 준다 — **이것이 실제 운영 모습이기도 하다.**

## 2. `make demo`가 하는 일

```
   ① 레지스트리 시드 (액션 3종: 가역·비가역·읽기전용)
   ② 예산 시드 (한도를 낮게 — 거부가 일어나야 한다)
   ③ 액션 실행 3건:
        - 가역 + 여유 있음   → ALLOW    → 원장 항목 (assumed)
        - 비가역 + 여유 있음 → REQUIRE_APPROVAL → 승인 → 실행
        - 가역 + 여유 없음   → DENY     → ★ 실행기 호출 0
   ④ 화해 트리거 (전날 실제 데이터)
   ⑤ 일간 리포트 출력 — assumed vs measured vs 게이트 오차
```

⚠️ **①~③은 fake 어댑터로도 돌지만, 영상은 라이브에서 찍는다.** 두 경로가 **같은 코드**를
타야 한다(`05-reconciliation.md` §7과 같은 규율).

## 3. 4분 영상 구성 (영어)

| 시각 | 비트 | 화면 | 말할 것 |
|---|---|---|---|
| 0:00–0:30 | **문제** | 실측 숫자 | *"We estimated a monitoring pipeline at $5/month. Measured: 52,438 time series — about 100× off. Agent observability watches tokens and latency. It does not watch the money the agent spends."* |
| 0:30–1:00 | **아키텍처** | 다이어그램 | 액션 → 게이트 → 원장 → (하루 뒤) 화해 |
| 1:00–1:45 | **실행** | 라이브 API | 액션 실행 → 원장 행 등장. **assumed와 그 수량·단가가 보인다** |
| 1:45–2:30 | ★ **거부** | 라이브 API | 예산 초과 → `DENY`. **`executed: false`** — *"This is enforcement, not an alert."* |
| 2:30–3:20 | ★ **화해** | 라이브 + BQ | 어제 액션의 `measured` 도착. **`assumed 0.02` vs `measured 1.90`** |
| 3:20–3:50 | ★ **게이트 오차** | 일간 리포트 | *"The gate approved this because it projected two cents. Its p95 error is 47×. We don't trust the gate — we measure it."* |
| 3:50–4:00 | **증거 + 한계** | GCP 콘솔 | Cloud Run 리비전 · 청구 페이지. 그리고 **공유 리소스 귀속은 못 푼다**는 한 줄 |

⚠️ **한계를 말하는 것이 마지막 10초의 값이다.** Production Readiness는 완벽함이 아니라
**무엇이 안 되는지 아는가**이다.

## 4. 영상 제작 유의

- **≤4분 · 영어 · 공개 URL** (요건). 초과는 실격 사유가 될 수 있다.
- **GCP 배포의 시각 증거**가 반드시 화면에 있어야 한다(요건).
- 콜드 스타트 대비: 촬영 직전 워밍 요청 1회(`04-agent-runtime.md` §6).
  **`min-instances`를 바꿔 찍고 되돌리지 않는다** — 영상 속 시스템이 제출물과 달라진다.
- 자막 권장. 비영어권 발화의 전달 손실을 줄인다.

⚠️ **영상이 병목이다.** 코드보다 오래 걸릴 수 있다. `tasks.md`에서 **08-30~31 이틀**을
통째로 배정한 이유다.

## 5. 데모용 상수 (REQ-704)

한 모듈(`demo/constants.py`)에 모은다:

```python
DEMO_BUDGET_LIMIT_USD      = Decimal("0.50")   # 거부가 일어날 만큼 낮게
DEMO_DENY_PROJECTED_USD    = Decimal("5.00")
RECONCILE_WINDOW_DAYS      = 2
WARMUP_REQUESTS            = 1
```

⚠️ **이 값들이 코드 곳곳에 흩어지면 영상 재촬영 때 반드시 하나를 놓친다.**
