## 1. 한 문장

**에이전트가 한 행동마다 원장 한 행을 쓰고, 그 행에 "우리가 추정한 값"과 "청구서가 말한 값"을
나란히 남겨, 둘의 차이를 시스템의 1급 산출물로 만든다.**

## 2. 이 구조를 결정한 세 가지 제약

### ① GCP는 실지출을 API로 안 준다 (측정된 사실)
Cloud Billing API discovery 전수 결과 **19개 메서드 중 지출을 읽는 것이 0개**다
(`services.skus.list`는 **가격표**지 사용량이 아니다). Budgets API의 `amount`는
**내가 설정한 금액**이다. 실지출 경로는 **BigQuery 결제 내보내기 하나뿐이고, 하루 지연된다.**

⇒ **즉시성과 정확성을 동시에 얻을 수 없다.** 그래서 **둘 다 적는다**(§3의 2단계 원장).
이건 타협이 아니라 이 도메인의 진실이고, **그 진실을 드러내는 것이 제품**이다.

### ② 추정은 안심시키는 쪽으로 틀린다 (측정된 사실)
레퍼런스 실측: 가정 "수백 시계열" vs 실제 **52,438** → 월 비용 **약 100배** 오차.
정가는 맞았고 **수량 가정**이 틀렸다.

⇒ 원장은 총액이 아니라 **총액을 만든 수량과 단가를 함께** 적는다(REQ-202).
⇒ 그리고 게이트는 추정으로 판정하므로, **게이트 자신의 오차를 측정한다**(REQ-307).

### ③ 4분 안에 전달돼야 한다
심사는 Innovation 40% · Architecture 30% · **Demo 30%**다. 내부 상태가 로그에만 있으면
없는 것과 같다(REQ-601). 실패 경로가 영상에 없으면 *"그래서 안 될 땐?"* 한 줄에 무너진다.

⇒ **거부와 오차가 화면에 보이는 것**이 아키텍처 요구사항이다.

## 4. 왜 이 경계인가 — 대안과 기각 사유

| 결정 | 대안 | 기각 사유 |
|---|---|---|
| **2단계 원장(assumed+measured)** | 실측만 적는다 | 하루 지연 → 액션 직후 장부가 비어 있다. **데모가 성립 안 함** |
| | 추정만 적는다 | 이 프로젝트의 논지가 *"추정은 틀린다"*인데 **추정을 답으로 내면 자기 배반** |
| **귀속 = 리소스 라벨** | 시간창 근사 | 동시 실행 시 귀속이 무너진다. 라벨은 **청구 행에 그대로 실려 온다** |
| **게이트 축 = 가역성** | severity | 심각도는 "급한가"지 "되돌릴 수 있나"가 아니다. 승인의 진짜 이유는 후자 |
| **Firestore** | Cloud SQL | 상시 인스턴스 = 상시 과금(REQ-705). Firestore는 유휴 시 0에 수렴 |
| **Cloud Run** | GKE | 트랙 요건은 "Google Cloud 1종 이상"이지 GKE가 아니다. GKE는 상시 과금 |
| **화해기 = Job + Scheduler** | API 안에서 폴링 | scale-to-zero가 깨진다 |

## 5. 불변식 (전부 테스트가 지킨다)

| id | 불변식 | REQ | 가드 |
|---|---|---|---|
| **I-1** | `assumed`는 쓰인 뒤 절대 바뀌지 않는다 | REQ-204 | G2 |
| **I-2** | 게이트 `DENY`면 실행기는 **호출되지 않는다** | REQ-303 | G1 |
| **I-3** | 모든 항목은 `attribution.method`와 그에 **일관된** `verifiability`를 갖는다 | REQ-203 | G3 |
| **I-4** | 모든 항목은 `budget_decision`을 갖는다 (게이트를 안 거친 항목은 없다) | REQ-301 | G4 |
| **I-5** | 액션 1회 = 원장 1행 (재시도가 행을 늘리지 않는다) | REQ-201 | G7 |
| **I-6** | 게이트 실행 중 어떤 과금 API도 호출되지 않는다 | REQ-701 | G5 |

⚠️ **불변식은 선언이 아니라 지워 보고 red가 나야 불변식이다.** `design/07-verification.md`.
