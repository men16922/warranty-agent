# L4 — 테넌트 신원 *(선택 · 08-27 판단)*

`Satisfies: REQ-701, REQ-702`

---

## 1. 무엇이 문제인가

스코프 설정은 **어느 리소스를 건드릴지**를 정한다. 그런데 **토큰은 여전히 전역**이다.
프로젝트 전역 신원 하나로 모든 테넌트의 리소스를 만질 수 있다면,
**경계는 코드 안의 필터**일 뿐이고 코드가 틀리면 경계가 없다.

> **자격증명 자체가 경계여야 한다.**

## 2. 어떻게

```
   테넌트 t  ──▶  전용 서비스 계정 sa-t@<project>.iam.gserviceaccount.com
                    권한: 그 테넌트의 리소스에만
                    ▲
                    │ Workload Identity Federation (장기 키 없음)
   Cloud Run 서비스 계정 ── impersonate ──┘
```

- 조치는 **impersonate한 자격증명**으로 실행된다
- 권한이 없으면 **API가 거부한다** — 코드 필터가 아니라 IAM이 막는다
- **장기 키 파일이 존재하지 않는다** (REQ-702)

## 3. 검증

이 요구사항은 **성공이 아니라 실패로 검증한다**:

- **Given** 테넌트 A의 자격증명
- **When** 테넌트 B의 리소스에 조치를 시도하면
- **Then** GCP가 **403으로 거부한다** — 우리 코드가 거부하는 게 아니다

⚠️ **우리 코드가 막는 테스트는 이 요구사항을 만족시키지 못한다.** 그건 필터가 있다는
증명이지 경계가 있다는 증명이 아니다.

## 4. ⚠️ 왜 선택인가

**가장 값진 항목인데 가장 무겁다** — SA 생성·IAM 바인딩·WIF 설정·impersonation 경로가 전부
실물 GCP 작업이고, 실패하면 배포 전체가 막힌다.

⇒ **배포·검증·롤백이 선 뒤 08-27에 여유가 있으면 넣는다.** 그때 없으면 안 넣고,
**리포트에 "테넌트 경계는 코드 필터다"라고 정직하게 적는다.**
