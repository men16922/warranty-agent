# L6 — 품질 게이트 (테스트 · 가드 · 변이 · 추적성)

`Satisfies: REQ-801, REQ-802, REQ-803, REQ-804 + 모든 REQ (추적성)`

---

## 1. 게이트

```
   make check = ruff + ruff format --check + mypy + pytest + trace
```

**조건 둘이 게이트를 게이트로 만든다**: **오프라인**(REQ-801)이고 **결정론적**(REQ-802).
이 둘이 무인 실행의 안전 조건이다 — 게이트가 과금하면 밤새 도는 루프가 밤새 돈을 쓴다.

## 2. 초록에 붙는 조건

| 조건 | 우리의 대응 |
|---|---|
| **시간** — 픽스처가 절대 시각을 하드코딩하면 통과는 달력이 움직이기 전까지만 참 | `FrozenClock` 포트 |
| **환경** — 선언 안 된 패키지 위에서 통과하면 새 클론은 못 통과 | `pyproject.toml`에 전부 선언 |
| **디스크** — 게이트가 레포에 없는 파일(`.env`)에 의존하면 이 기계에서만 참 | `environ`을 주면 디스크를 안 읽는다 |
| **하중** — 행복 경로만 태운 가드는 안전망을 지워도 초록 | **모든 가드는 지워 보고 red 확인** |
| **skip** — 검사 안 하는 게이트와 통과한 게이트가 같은 색 | 게이트 숫자에 **날짜와 잰 기계**를 붙인다 |
| **관측 지점** — 독자가 안 읽는 물건에 물으면 결함을 그림자로 센다 | 가드는 **응답·저장소**에 묻는다 |

## 3. 가드

| id | 지키는 것 | 관측 지점 | 변이 |
|---|---|---|---|
| **G1** | `DENY`/`MANUAL`이면 실행기 **호출 0** (REQ-403) | `RecordingExecutor.call_count` | 게이트를 자문으로 |
| **G2** | `assumed` 불변 (REQ-505) | 화해 후 항목 | 화해가 `assumed`를 덮게 |
| **G3** | 귀속 방법 ↔ 검증 가능성 일관 (REQ-504) | 저장 항목 전수 | 매핑에 잘못된 짝 |
| **G4** | 모든 항목에 `decision` (REQ-401) | 저장 항목 전수 | 게이트 우회 경로 |
| **G5** | 게이트 중 라이브 어댑터 생성 0 (REQ-801) | 어댑터 팩토리 카운터 | 라이브 클라이언트 주입 |
| **G6** | **spec의 상태 주장 ↔ 현실** (추적성) | `requirements.md` 파싱 | REQ 추가 후 테스트 미작성 |
| **G7** | 조치 1회 = 원장 1행 (REQ-501) | 재시도 후 항목 수 | 같은 id 덮어쓰기 허용 |
| **G8** | ★ **`improved`는 저장이 아니라 유도** (REQ-502) | 항목 속성 | `improved`를 별도 저장 필드로 |
| **G9** | ★ **검증 불가 조치는 `AUTO`가 안 된다** (REQ-402) | 판정 다섯 칸 | 검증 가능성 축 제거 |

⚠️ **G9가 이 프로젝트의 정책을 지키는 가드다.** 축을 빼도 다른 테스트는 다 통과한다 —
그래서 별도 가드가 필요하다.

### 3.1 G6 — spec-driven과 spec-decorated를 가른다

`requirements.md`를 파싱해 **상태가 주장하는 것을 현실에 맞댄다**:
`IMPLEMENTED`면 테스트가, `VERIFIED`면 **red가 확인된 변이 기록**이 있어야 한다.

**형제 검사 셋을 함께 한다**: 테스트 · 태스크 · 설계 귀속.
⚠️ **①만 묻는 G6는 절반짜리다.**
**공허 통과 방지**: 파싱된 요구사항이 최소 개수 미만이면 그 자체가 실패다.

## 4. 변이 검증

**지워 보고 red가 나오지 않은 가드는 가드가 아니다.**

`scripts/mutate.sh`가 한 스크립트 안에서: 기준선 → 변이 → **전체 스위트** → 복구 →
**초록 복귀 확인** → **백업 대조 잔여 확인**.

⚠️ 이 하네스 자신이 세 번 틀렸고 전부 기록돼 있다(`docs/evidence/mutations.md`):
출력 문자열로 판정(red를 초록으로 읽음) · `git status`로 잔여 확인(무관한 변경을 오인) ·
stale `.pyc`(복구했는데 red 유지). ⇒ **종료 코드 · 백업 대조 · 바이트코드 끄기.**

⚠️ **문법을 깬 변이는 red로 세지 않는다.** 컴파일 실패는 검증이 아니다.

## 5. 테스트 계층

| 계층 | 어댑터 | 게이트 |
|---|---|---|
| 단위 (판정 행렬 · 회복 판정 · 비용) | fake | ✅ |
| 통합 오프라인 (provision→remediate→verify→rollback 전 경로) | fake | ✅ |

⚠️ 라이브는 게이트에 안 넣는다. 대신 **손으로 돌리고 증거를 남긴다** —
`docs/evidence/`에 날짜·명령·출력. **"한때 통과했다"와 "지금 재현된다"는 다르다.**
