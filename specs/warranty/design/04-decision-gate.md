# L4 — 판정 게이트 (축이 셋이다)

`Satisfies: REQ-401, REQ-402, REQ-403, REQ-404, REQ-405, REQ-406`

---

## 1. 판정 행렬 (REQ-402)

| 가역성 | 검증 가능 | 예산 여유 | 판정 |
|---|---|---|---|
| 가역 | 가능 | 있음 | **`AUTO`** |
| 가역 | **불가** | 있음 | **`APPROVE`** ← 이 프로젝트의 정책 |
| 비가역 | 가능 | 있음 | `APPROVE` |
| 비가역 | 불가 | 있음 | `MANUAL` |
| 아무 | 아무 | **없음** | `DENY` |

### 왜 축이 셋인가

- **가역성** — 사람이 개입해야 하는 이유는 급해서가 아니라 **틀렸을 때 되돌릴 수 없어서**다.
  `severity`는 "얼마나 급한가"만 말한다.
- **★ 검증 가능성** — **되돌릴 수 있어도 나아졌는지 확인할 수 없으면 자동으로 하지 않는다.**
  확인 못 하는 자동화는 자동화가 아니라 **방치**다. 이 축이 이 프로젝트의 주장이다.
- **예산 여유** — 돈은 언제나 비가역이다. 초과분은 되돌릴 수 없다.

### 검증 가능성은 어디서 오나
계약의 존재와 신호의 도달 가능성에서 **유도한다** — 조치가 선언하지 않는다.

```
   verifiable = contract is active
                and contract.health_signal is readable now
```

⚠️ **조치가 자기 검증 가능성을 주장하게 하면 모든 조치가 검증 가능하다고 말한다.**

## 2. `DENY`·`MANUAL`은 집행이다 (REQ-403)

**실행기가 호출되지 않는다.** 판정만 적고 실행을 막지 않아도 **로그는 똑같아 보인다** —
이 프로젝트에서 가장 쉽게 조용히 깨지는 지점이고, 가드 G1이 실행기 호출 횟수로 지킨다.

## 3. 예약 프로토콜 (REQ-405)

```
   reserve(budget, projected)   ── 트랜잭션 ── headroom 부족이면 DENY
   execute
   settle(budget, reservation, actual)   ── 트랜잭션
```

⚠️ `settle`이 안 돌면 예산이 **조용히 잠긴다.** 예외 경로에서도 돌게 하고
`unsettled_reservations`를 지표로 낸다 — 잠긴 예산은 "예산 없음"과 구분이 안 된다.

## 4. 승인 (REQ-404)

승인 시 **게이트를 다시 평가한다.** 대기 중에 예산이 소진됐거나 계약이 `retired`가 됐을 수 있다.
승인은 *"비가역성/검증 불가에 대한 동의"*지 **예산 면제나 계약 면제가 아니다.**

## 5. 파괴적 조치 (REQ-406)

삭제·종료 계열은 가역성 판정과 **무관하게** 최소 `APPROVE`다.
⚠️ 이 목록은 **하나라도 빠지면 그 조치가 자동 실행된다.** 형제 집합이므로 **세는 순간 전부 센다.**

## 6. 게이트가 조용히 깨지는 방식

| 깨짐 | 증상 | 가드 |
|---|---|---|
| 판정은 하는데 실행을 안 막음 | 로그가 동일 | **G1** |
| 게이트를 안 거친 실행 경로 | 항목에 판정 없음 | **G4** |
| 행복 경로만 태운 테스트 | 다섯 칸 중 일부가 도달 불가 | 판정 **다섯 칸을 값으로 명시** |
| 검증 가능성을 조치가 주장 | 전부 `AUTO`가 됨 | 유도되는지 묻는 테스트 |
