## 1. 한 문장

**인프라를 만든 에이전트가 그것을 어떻게 고쳐야 하는지도 함께 적어 두고,
조치한 뒤 실제로 나아졌는지 다시 재서, 안 나아졌으면 원자적으로 되돌린다.**

## 2. 이 구조를 결정한 것 — GCP 전용이라는 선택

중립적인 운영 에이전트는 **모든 클라우드에서 표현 가능한 조치만** 할 수 있다.
그 제약이 세 가지를 불가능하게 만든다. GCP 하나에 올인하면 셋 다 가능해진다.

| 중립성이 막는 것 | GCP 전용이 여는 것 | 어디 |
|---|---|---|
| 신호를 정규화하면 provider 고유 정보가 깎인다 | **Cloud Monitoring을 그대로 읽는다** | `design/02` |
| 되돌림이 점진적이면 자동 롤백을 못 믿는다 | **Cloud Run 트래픽 전환 = 원자적, 그리고 배분으로 증명된다** | `design/03` |
| 조치당 비용을 귀속할 공통 수단이 없다 | **리소스 라벨이 결제 내보내기 행에 실려 온다** | `design/05` |
| 자격증명이 전역이면 경계가 코드 필터다 | **테넌트별 SA + WIF** *(선택)* | `design/07` |

**그리고 이 넷을 잇는 것이 운영 계약이다** — Day-1이 Day-2에 넘기는 산출물(`design/01`).

## 3. 정책 한 줄

> ⛔ **검증할 수 없는 조치는 자동으로 실행하지 않는다.**

이것이 판정 게이트의 축 하나가 되고(REQ-402), 계약 없는 리소스가 `MANUAL`이 되는 이유이며
(REQ-104), 리포트에 `unverifiable` 칸이 있는 이유다(REQ-508).

**확인 못 하는 자동화는 자동화가 아니라 방치다.**

## 4. 왜 이 경계인가 — 대안과 기각

| 결정 | 대안 | 기각 사유 |
|---|---|---|
| **계약을 프로비저닝 산출물로** | 런북을 따로 쓴다 | 손으로 적은 것은 **낡는다**. 리소스는 바뀌고 문서는 안 바뀐다 |
| **검증을 1급으로** | 실행 성공을 성공으로 | **이 프로젝트의 논지 자체** |
| **판정 축에 검증 가능성** | 가역성 + 예산 둘 | 되돌릴 수 있어도 **확인 못 하면 자동은 방치**다 |
| **Cloud Run 트래픽 롤백** | K8s 롤아웃 | 점진적이라 중간 상태가 있고, **4분 영상에 안 담긴다** |
| **Firestore** | Cloud SQL | 상시 인스턴스 = 상시 과금 |
| **모델은 애매할 때만** | 모든 판정을 모델에 | 판정이 비결정적이 되어 REQ-802가 깨진다 |
| **비용은 한 열** | 비용을 주제로 | 이건 **자동화 프로젝트**다. 비용은 책임의 한 축 |

## 5. 불변식

| id | 불변식 | REQ | 가드 |
