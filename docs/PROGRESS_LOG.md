## 2026-08-29 — GPU 쿼터가 없어서 갈래가 정해졌고, 조치가 둘이 됐다 (gate 403 → 422)

- **Status**: ⛔ **결정 대기가 끝났다 — 갈래 ⓒ 확정.** 계획의 P0가 답을 냈고, 어느
  갈래에서도 한다고 미리 박아 둔 P1(두 번째 조치)을 했다.
- **⭐ P0 — 답을 준 것은 목록이 아니라 실제 요청이었다**: `gcloud beta quotas info list`는
  **모든 프로젝트에 L4/RTX 쿼터 ID 넷을 똑같이** 보여 준다. `describe`의
  `dimensionsInfos.details`는 비어 있고, Monitoring의 `quota/limit` 시계열은 0건이다
  (그 쿼터를 한 번도 안 썼으니 당연하다). **셋 다 답을 못 준다.**
  ⇒ Cloud Run Admin v2의 **`validateOnly=true`**로 물었더니 검증 단계에서 그대로 돌아왔다:
  `You do not have quota for using GPUs with/without zonal redundancy` —
  `us-central1`·`europe-west4`·`asia-southeast1`, 이중화 두 모드 **전부**.
  ⭐ **리소스는 하나도 안 만들었다** — 비용 0, 잔여물 0(서비스 넷 그대로).
- **⇒ ⓑ는 죽었다**: 증설은 자격이 되지만(`isEligible: true`) 제출 09-01 · 크레딧 09-06
  안에 승인이 보장되지 않는다. 아티클의 goodput 수치는 **재현이 아니라 문제 제기로만** 쓴다.
- **⭐ P1 — 조치가 둘이 됐다(T2-5)**: 문법 `traffic:<revision>` · `concurrency:<n>`.
  구분자 없는 옛 형태는 그대로 트래픽 전환이다 — 08-28 원장이 그 형태라 깨면 **이미
  실물에서 참인 기록이 재현 불가**가 된다.
- **⭐ 대가가 없었다는 것이 요점이다**: 동시성 변경은 Cloud Run이 **새 리비전**을 만든다
  ⇒ 되돌리기는 이미 원자적이라고 되읽어 증명한 트래픽 전환이다. **롤백 코드 0줄 추가.**
- **⛔ 가장 조용한 함정을 하나 막았다(M-261)**: 롤백이 한 번이라도 돌면 배분은 특정
  리비전에 **고정**된다. 그 상태에서 템플릿만 바꾸면 새 리비전은 **아무 요청도 안 받는다** —
  조치는 200을 받고, 검증은 `not_recovered`를 내고, 롤백이 돈다. 원장은 *"고쳤는데 안
  나아졌다"*고 적지만 **고친 적이 없다.** ⇒ 동시성 변경은 트래픽을 **LATEST로 함께** 돌린다.
- **⭐ 도구 표면도 열었다(M-264)**: `target_revision` → `action`. 이름이 그대로였으면
  두 번째 조치는 **코드에는 있고 에이전트는 못 부르는 능력**이었다 — 데모에 없는 것과 같다.
- **⛔ 스윕이 낡은 변이를 잡았다 — M-234가 조용히 무효였다**: P1이 실행기를 문법 해석 +
  분기로 바꾸면서 M-234의 perl 패턴이 가리키던 줄이 사라졌다. 패턴이 안 맞으면 변이는
  **적용되지 않고**, 그 변이는 red 확인을 **공짜로 유지한다.** 스위트가 준 것도 아니라
  신선도 가드도 안 운다. ⇒ **코드를 고치면 그 줄을 가리키던 변이도 함께 낡는다.**
- **Verified**: `make check` **422 passed** · 전체 스윕 **264종 전부 red**, `❌` 0,
  복구 264 · 잔여 0 (1320줄). 새 변이 M-256~M-264 아홉.
- **⛔ 안 한 것을 적어 둔다**: 배포를 안 했다. 프로덕션은 여전히 `00005-8x9`이고,
  동시성 조치는 **오프라인까지만 참이다**(PRINCIPLES #3). 그래서 `submission/SCRIPT.md`도
  안 건드렸다 — 대본이 안 도는 것을 말하면 그건 대본이 아니라 주장이다.
- **Next**: T2-5를 배포해 실물로 만들 것인가 결정 → 부하 켠 채 영상(T8-3) → 제출(09-01).

  `executed 1 · improved 0 · rolled_back 1`을 냈다. 게이트 거부 비트도 실물에서 확인 —
  `MANUAL` · 규칙 `irreversible and not verifiable` · 6.3s. 대본의 출력은 전부 실측이다.
- **푸시 전 점검**: API 키·개인키·토큰 **0건**, `.env`는 이력에도 없다. public으로 정한 이유는

- **⛔ 이 세션의 가장 큰 발견 — 논지가 약하다**: *"조치 후 재측정해 안 나아졌으면 롤백"*은
  Flagger·Argo Rollouts·Kayenta가 이미 성숙하게 한다. *"이거 Flagger 아니야?"*에 답할 말이
  없고, 조치가 트래픽 전환 하나뿐이라 더 그렇다. **기계가 약한 게 아니라 프레이밍이 틀렸다.**

  요청 100% 성공, **goodput 50%**. `executed ≠ improved`의 가장 순수한 형태이고 LLM 서빙에서는
  헬스체크가 원리적으로 못 잡는다. ⭐ 게다가 동시성 변경은 **새 리비전을 만들어서** 롤백이
  지금 메커니즘 그대로다 — 어댑터 하나 + `KNOWN_KINDS` 한 줄이면 된다.
- **Blockers**: ① 결정 대기(ⓑ 이동 vs ⓒ 서사만) ② `warranty-hack`의 **L4 GPU 쿼터 미확인**
