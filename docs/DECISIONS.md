# DECISIONS — warranty

> ADR. **결정 · 이유 · 기각된 대안**만. 상세 설계는 `specs/`가 권위.
> ⚠️ 결정이 바뀌면 **이 파일과 spec을 고친다.** 코드만 고치는 것은 금지.

---

## D1 — ★ GCP 전용으로 간다. 중립성을 명시적으로 포기한다 (2026-08-19)
`Affects: 논지 전체`

중립적인 에이전트는 **모든 클라우드에서 표현 가능한 조치만** 할 수 있고, 그 제약이
검증·원자적 롤백·조치당 비용 귀속을 **전부 불가능하게** 만든다.

**기각**: 멀티클라우드 어댑터 — 범위 밖이 아니라 **논지의 반대편**이다.

## D2 — ★ 프로비저닝이 운영 계약을 산출한다 (2026-08-19)
`Affects: REQ-1xx`

Day-1과 Day-2를 **하나의 아이디어로** 잇는 유일한 장치. 없으면 이 프로젝트는 프로비저닝
도구와 운영 도구 둘이다.

**기각**: 런북을 따로 작성 — **손으로 적은 것은 낡는다.** 리소스는 바뀌고 문서는 안 바뀐다.
⇒ 계약은 **생성 API 응답에서 유도**한다. 사람이 정하는 건 회복 기준 하나뿐이다.

## D3 — ★ 검증을 1급으로: "실행됨 ≠ 나아졌음" (2026-08-19)
`Affects: REQ-2xx, REQ-502`

`executed`·`improved`·`rolled_back`을 **따로** 기록한다.
**기각**: 하나의 `success` — 합치는 순간 이 프로젝트의 논지가 사라진다.
⇒ `improved`는 저장하지 않고 **검증 결과에서 유도**한다(G8).

## D4 — ★ 판정 게이트의 축에 **검증 가능성**을 넣는다 (2026-08-19)
`Affects: REQ-402`

> **검증할 수 없는 조치는 자동으로 실행하지 않는다.**

되돌릴 수 있어도 나아졌는지 확인할 수 없으면 자동은 **방치**다.
**기각**: 가역성 + 예산 2축 — 그러면 "돌려도 되지만 확인은 못 하는" 조치가 `AUTO`가 된다.
⇒ 검증 가능성은 **계약의 존재와 신호 도달 가능성에서 유도**한다. 조치가 주장하지 않는다.

## D5 — ★ 롤백은 Cloud Run 트래픽 전환이고, 배분을 다시 읽어 **증명**한다 (2026-08-19)
`Affects: REQ-3xx`

원자적이고 즉시이며 중간 상태가 없다. **"롤백했다"는 주장이고 "트래픽이 이전 리비전으로
갔다"는 측정이다.**
**기각**: K8s 롤아웃 — 점진적이라 중간 상태가 있고 **4분 영상에 안 담긴다.**

## D6 — ★ 롤백 후에도 재측정한다 (2026-08-19)
`Affects: REQ-304`

되돌렸는데 신호가 안 돌아오면 **원인이 조치가 아니었다**는 뜻이고, 그건 에스컬레이션 사유다.
검증의 인과 한계를 부분적으로 메우는 **약한 자연 실험**이기도 하다.

## D7 — ★ 모델은 **애매할 때만** 판단하고, 근거를 문장으로 남긴다 (2026-08-19)
`Affects: REQ-204`

계약의 `tolerance` 안쪽에서만 모델을 부른다.
**기각(양쪽)**: 전부 규칙 — 임계값이 또 애매한 경우를 만든다 / 전부 모델 — 판정이
비결정적이 되어 REQ-802가 깨진다.
⚠️ **이 자리가 없으면 이 시스템에서 LLM은 파서일 뿐이다.**

## D8 — 롤백 계획은 조치 **전에** 고정한다 (2026-08-19)
`Affects: REQ-301`
조치 후에 찾으면 **바로 그 조치가 깨뜨린 상태에 의존**한다. 롤백의 추가 API 호출 = 0.

## D9 — 비용은 **주제가 아니라 책임의 한 축** (2026-08-19)
`Affects: REQ-5xx`
이건 자동화 프로젝트다. 비용은 리포트의 한 열(`wasted_usd`)로 남고,
**BQ 청구 화해는 선택**이다(하루 지연이라 크리티컬 패스에 두지 않는다).
⚠️ 이미 만든 `CostFact`·`Attribution`·불변 규칙은 **그대로 쓰인다** — 버리는 코드 0.

## D10 — 게이트는 오프라인·무과금, 포트/어댑터는 그 전제 (2026-08-19)
`Affects: REQ-801, REQ-802`
포트는 설계 취향이 아니다 — 이 요구사항이 없으면 만족 불가능하다.
`environ`을 주면 디스크를 안 읽는다(결정론).

## D11 — 전용 GCP 프로젝트 · GKE/상시 VM/Cloud SQL 금지 (2026-08-19)
`Affects: REQ-805`
teardown이 **프로젝트 삭제 하나**로 끝나야 한다. 리소스를 하나씩 지우면 반드시 뭔가 남는다.

## D12 — 테넌트 신원(SA + WIF)은 **선택**, 08-27 판단 (2026-08-19)
`Affects: REQ-7xx`
**가장 값진 항목인데 가장 무겁다.** 배포·검증·롤백이 선 뒤에만 넣는다.
없으면 리포트에 **"테넌트 경계는 코드 필터다"라고 정직하게 적는다.**

## D13 — 프로젝트명 `warranty` (2026-08-19, D1(구 `fleet-ledger`)을 대체)
*"Infrastructure that ships with a warranty."* 계약 은유가 그대로 아키텍처다.
영어 심사위원에게 한 번에 전달된다.

## D14 — 무인 루프(overnight harness)를 개발 방식으로 쓴다. 경계는 게이트다 (2026-08-23)

**결정**: 밤샘 무인 루프가 `[auto]` 태그가 붙은 백로그만 소비한다. 판정은 `make check`(오프라인·
결정론·무과금, D10)이고, 루프는 커밋하되 **push하지 않는다.** 권한 경계는
`scripts/overnight/overnight-settings.json`이며 `gcloud`·`bq`·`docker`·`terraform`·`uv`·
`pytest -m live`를 **전부 deny**한다. `make demo`만 예외로 allow다 — REQ-803이 결정론을 요구하고
게이트 안의 테스트가 그것을 집행하기 때문이다.

**이유**: D10이 이미 "게이트는 오프라인·무과금"을 못 박았고, 그 전제가 있어야 무인 실행이
안전하다. 태그 없는 항목을 루프가 스스로 `[auto]`로 **승격하지 않는 것**이 보안 기본값이다 —
실제로 백로그가 말랐을 때 루프가 승격을 거부하고 종료했다.

**영향**: 오프라인으로 판정 가능한 일은 밤에 처리된다. 반대로 **실물 클라우드가 필요한 일은
원리상 루프가 못 한다** — T0-3·T2-*·T7-*는 사람이 한다. 이 비대칭이 지금 병목의 모양이다.
