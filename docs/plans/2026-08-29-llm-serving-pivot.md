작성 2026-08-29 04:35 UTC · **제출까지 67시간** (09-01 00:00 UTC = 09:00 KST)
근거 아티클: 사용자가 발행한 *"Cloud Run RTX PRO 6000 GPU · vLLM · Gemma 4"* 실습기

> ⛔ **이 계획은 끝났다. 후속: [`2026-08-29-cost-axis.md`](2026-08-29-cost-axis.md).**
> P0는 답이 났고(§0) P1은 구현됐다(T2-5). 그러나 **이 계획이 답하려던 질문 자체가 틀렸다** —
> Flagger 반론의 답은 *"조치를 늘리는 것"*이 아니라 *"조치의 비용을 말하는 것"*이었다.
> 그 재정립은 후속 문서가 소유한다. 여기는 GPU 쿼터 확인의 근거로만 남는다.

## 0. ⛔ 결정 — **갈래 ⓒ 확정** (2026-08-29 · P0 실행 결과)

**P0의 답: `warranty-hack`에 L4 GPU 쿼터가 없다.**

리소스는 하나도 만들지 않고 Cloud Run Admin v2의 `validateOnly=true`로만 물었다.
세 리전 · 이중화 두 모드에서 전부 같은 거절이다:

> `template.scaling.max_instance_count: You do not have quota for using GPUs with
> zonal redundancy.` — `us-central1` · `europe-west4` · `asia-southeast1`

증거: [`../evidence/gpu-quota-probe-2026-08-29.log`](../evidence/gpu-quota-probe-2026-08-29.log)

⚠️ **쿼터 ID가 목록에 있는 것은 "있다"가 아니다.** `gcloud beta quotas info list`는 모든
프로젝트에 같은 ID 넷을 보여 주고, `describe`의 `dimensionsInfos.details`는 **비어 있다.**
Monitoring의 `quota/limit` 시계열도 0건이다 — 그 쿼터를 한 번도 안 썼으니 당연하다.
⇒ **목록도 describe도 Monitoring도 답을 못 준다.** 답을 준 것은 실제 요청의 검증 응답뿐이다.

⇒ §5 중단 기준의 「P0 직후」 행이 발동했다: **ⓑ는 죽었다. ⓒ로 간다.**
증설 신청은 자격이 있으나(`quotaIncreaseEligibility.isEligible: true`) 승인이 제출
기한(09-01 09:00 KST) 안에 보장되지 않고, 크레딧도 09-06 만료다. **걸지 않는다.**

### ✅ 그래도 P1은 했다 — 그리고 그게 이 계획에서 살아남은 부분이다

계획이 미리 박아 둔 대로다: *"P1(동시성 조치)은 어느 갈래에서도 한다."*

- `concurrency:N` 조치가 실물 어댑터·문법·테스트·변이(M-256~M-263)까지 들어갔다.
- **롤백 코드는 한 줄도 안 늘었다** — 동시성 변경은 새 리비전을 만들고, 되돌리기는
  이미 원자적이라고 되읽어 증명한 그 트래픽 전환이다.
- ⇒ *"결국 배포 롤백이잖아"*에 대한 답이 생겼다: **조치는 둘이고, 둘째는 배포와 무관하다.**

⛔ 남은 정직한 한계: *"실제로 LLM 서빙에 붙여 봤나"*에는 **아니오**다. 아티클의 goodput
측정치는 **재현한 결과가 아니라 문제 제기의 근거로만** 인용한다 — §4 ⓒ가 적어 둔 대가 그대로다.

## 1. 왜 옮기나 — 지금 프레이밍은 이길 수 없는 싸움이다

현재 논지: *"조치 후 재측정해서 안 나아졌으면 롤백한다."*

⛔ **그건 이미 성숙한 제품이 여럿 한다.** Flagger · Argo Rollouts · Spinnaker Kayenta가
카나리 배포에서 p95·오류율을 재고 자동 롤백한다. 심사위원이 물을 한 문장:

> *"이거 Flagger 아니야?"*

지금 대본으로는 **답할 말이 없다.** 조치가 *"트래픽 전환"* 하나뿐이라 더 그렇다.

## 2. 아티클이 이미 답을 갖고 있다

아티클 §A4에서 측정한 것:

| 동시성 | 요청 성공률 | **Goodput**(TTFT≤2s · 전체≤30s) |
|---:|---:|---:|
| 8 | 100% | **100%** |
| 16 | **100%** | **50%** |

> **"요청 자체는 모두 성공했지만 절반이 응답 시간 목표를 지키지 못했다."**

⭐ **이 한 줄이 warranty의 논지 그 자체다.** 다른 도메인이 아니라 **가장 순수한 형태**다:

```
executed = 성공  ·  improved = 아님
```

LLM 서빙에서는 **헬스체크가 원리적으로 못 잡는다.** 200이 뜨고, 토큰이 나오고, 로그는 초록인데
**절반이 SLO를 못 지킨다.** 지연이 아니라 **goodput**을 봐야 보이고, goodput을 자동화에
물려 둔 팀은 거의 없다.

### 그리고 Flagger 비교가 죽는다

| | Flagger | 옮긴 뒤 warranty |
|---|---|---|
| 대상 | 배포(카나리) | **LLM 서빙 운영 파라미터** |
| 조치 | 트래픽 비율 | **동시성·인스턴스** |
| 신호 | HTTP p95·오류율 | **goodput / TTFT** |
| 언제 | 배포할 때만 | 아무 때나(Day-2) |

*"배포"* 얘기가 한 번도 안 나온다. **비교 대상이 사라진다.**

## 3. ⭐ 결정적으로 — 코드를 거의 안 고쳐도 된다

동시성을 바꾸면 **Cloud Run이 새 리비전을 만든다.**
⇒ 롤백은 **이전 리비전으로 트래픽 전환** — **지금 있는 그 메커니즘 그대로다.**

| 부품 | 상태 |
|---|---|
| 계약·판정 게이트·원장·리포트 | **그대로** |
| 신호 읽기 | **그대로** (`metric_type`이 이미 인자다) |
| 롤백·되읽기 | **그대로** (동시성 변경 = 새 리비전) |
| 조치 실행기 | ⚠️ **하나 추가** — 동시성 바꾼 리비전 생성 |
| 계약의 리소스 종류 | ⚠️ `KNOWN_KINDS`에 한 줄 |

**바꿔야 할 코드는 어댑터 하나와 표 한 줄이다.** 나머지는 전부 이미 실물에서 돈다.

## 4. 세 갈래

### ⓐ 전면 이동 — 아티클을 그대로 재현

RTX PRO 6000 + Gemma 4 31B + Run:ai Streamer + Direct VPC Egress.

- ⛔ **콜드 스타트 4분 31초** — **영상 전체 길이보다 길다.** 촬영 중 절대 못 깨운다.
- ⛔ GPU 쿼터가 Pre-GA 허용 목록이다. 이 프로젝트(`warranty-hack`)에 있는지 **미확인**.
- ⛔ 58GiB 모델을 GCS에 올리고 캐시하는 준비만 몇 시간.
- ⛔ 67시간에 영상까지 있다.

**판정: 안 된다.** 실패하면 제출물 자체가 없다.

### ⓑ ★ 부분 이동 — LLM 서빙을 대상으로, 구성은 가볍게 (**추천**)

vLLM은 쓰되 **작은 모델 + L4**로 간다. 논지에 필요한 것은 31B가 아니라
**동시성을 올리면 goodput이 무너지는 서비스** 하나다. 그건 작은 모델에서도 똑같이 난다.

- ✅ 콜드 스타트가 분 단위 → **초 단위**로 내려온다
- ✅ L4는 GA라 쿼터 확보가 훨씬 쉽다
- ✅ 비용이 한 자릿수 달러
- ✅ **아티클의 31B 측정치는 "왜 이 문제가 중요한가"의 근거로 인용**한다 — 재현 대상이 아니라 **동기**다

### ⓒ 서사만 이동 — GPU를 아예 안 쓴다

지금 데모(`demo-target`)를 그대로 두고, 아티클 숫자를 **문제 제기**로만 인용.

- ✅ 비용·리스크 0
- ⛔ *"그래서 실제로 LLM 서빙에 붙여 봤어?"*에 **아니오**라고 답해야 한다
- ⛔ Flagger 반론이 안 죽는다

## 6. 옮긴 뒤의 한 문장

| | |
|---|---|
| 지금 | *"Remediation agents report success. Executing is not improving."* |
| 옮기면 | **"Your LLM endpoint returns 200 for every request. Half of them missed the SLO. Your health check cannot see the difference — and neither can the agent tuning it."** |

**그리고 대회 트랙이 Fortified Enterprise Fleet다.** 지금 이 트랙에 제출될 물건 대부분이
*"에이전트가 뭘 했다"*를 보여 준다. 이건 **에이전트가 LLM 서빙 파라미터를 만졌을 때
그게 도움이 됐는지 따지는 것** — 요즘 실제로 아무도 안 하는 자리다.

## 8. 안 하는 것

- **31B 모델 재현** — 콜드 스타트가 영상보다 길다. 아티클을 **인용**하지 재현하지 않는다.
- **Run:ai Model Streamer · Direct VPC Egress** — 논지에 안 쓰인다.
- **goodput을 커스텀 지표로 만들기** — Monitoring 커스텀 지표는 시간을 먹는다.
  1차는 `request_latencies` p95로 간다(이미 돈다). goodput은 **말로** 설명한다.
  ⚠️ 여유가 남으면 그때 올린다 — 먼저 하면 P5가 늦어진다.
