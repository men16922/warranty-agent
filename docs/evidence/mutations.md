## ⚠️ 하네스 자신이 다섯 번 틀렸다 (2026-08-19)

레퍼런스가 경고한 그대로, **변이 하네스가 먼저 결함을 냈다.** 기록해 둔다 —
이 기록이 없으면 다음 사람이 같은 순서로 밟는다.

1. **판정을 출력 문자열로 했다.** 변이는 실제로 red를 냈는데 `tail -1`이 요약 줄이 아니라
   short summary의 마지막 줄을 집어 **"초록"으로 읽었다.** ⇒ **종료 코드로 판정한다.**
   (곁가지로: `addopts`의 `-q`와 하네스의 `-q`가 겹쳐 `-qq`가 되면서 요약 줄 자체가
   사라져 있었다 — "몇 건이 죽었나"를 못 적고 있었다.)
2. **잔여 확인을 `git status`로 했다.** 커밋 안 된 다른 작업이 **변이 잔여로 오인**됐다.
   ⇒ **백업과 파일 단위로 대조한다.**
3. **stale `.pyc`에 속았다.** 소스는 복구됐는데 `__pycache__`가 남아 테스트가 옛 코드를 보고
   red를 유지했고, 그것이 **"복구 실패"로 읽혔다.** 다음 변이는 기준선이 red라 중단됐다.
   ⇒ `PYTHONDONTWRITEBYTECODE=1` + 복구 시 `__pycache__` 제거.

4. **변이 대상 파일이 없는데 조용히 넘어갔다.** 프로젝트 이름을 바꾸고 이 스크립트의 경로를
   안 고쳤더니, 변이가 **적용되지 않은 채** "가드가 하중을 안 받는다"로 보고됐다.
   ⇒ `backup()`이 파일 부재를 **판정이 아니라 오류**로 낸다.
5. **파일은 있는데 패턴이 안 맞아 변이가 조용히 무효였다.** 설정 변수 접두사를 바꾼 뒤
   패턴을 안 고쳤을 때. 존재 검사로는 못 잡는 별개의 실패 모드다.
   ⇒ 변이 후 **파일이 실제로 바뀌었는지 확인**하고, 안 바뀌었으면 판정을 내지 않는다.

**교훈**: ⑤(초록 복귀)와 ⑥(잔여 대조)이 있었기 때문에 다섯이 전부 드러났다.
**변이가 red를 냈는지만 보는 하네스였다면 다섯 다 통과했을 것이다.**
그리고 ④⑤는 **초록을 "가드 없음"으로 잘못 읽게 만드는** 종류라 가장 위험하다 —
없는 가드를 만들러 가거나, 있는 가드를 지우게 된다.

### ⛔ 예약이 **기존 가드 둘을 가렸다** — 이번 판의 가장 큰 발견

REQ-405를 넣자마자 **M-18(G1: 막는 판정인데 실행기를 부른다)과 M-27(승인이 게이트를 면제)이
초록으로 돌아섰다.** 코드가 틀려서가 아니라, 그 둘의 기존 증거가 전부 **예산이 마른 케이스**로
쓰여 있었기 때문이다 — 판정 집행을 지워도 이제는 **예약이 실행기보다 먼저 막는다.**

```
   기존 증거:  DENY(여유 없음)      → 판정 집행을 지워도 → 예약이 막는다 → 초록
   되돌린 증거: MANUAL(여유 남음)   → 판정 집행을 지우면 → 실행된다     → red
```

`improved`를 `executed`로 세는 변이는 **버그처럼 안 생겼다.** 코드는 돌고, 리포트는
