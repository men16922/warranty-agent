> **지워 보고 red가 나오지 않은 가드는 가드가 아니다.**
> 요구사항 상태를 `VERIFIED`로 올리려면 여기에 **red 확인** 행이 있어야 하고,
> `tools/spec_trace.py`가 그것을 읽어 집행한다(가드 G6).

**절차** (`specs/fleet-ledger/design/07-verification.md` §4) — 전부 `scripts/mutate.sh` 안에서:
① 기준선 → ② 변이 → ③ 전체 스위트가 red인가·**몇 건이 죽었나** → ④ 복구 →
⑤ **초록 복귀 확인** → ⑥ **백업 대조로** 잔여 확인.

⚠️ **문법을 깬 변이는 red로 세지 않는다** — 컴파일 실패는 검증이 아니다.
⚠️ **전체 스위트에 묻는다** — 한 파일에만 물으면 "가드 없음"으로 잘못 읽는다.

## ⚠️ 하네스 자신이 세 번 틀렸다 (2026-08-19)

레퍼런스가 경고한 그대로, **변이 하네스가 먼저 결함을 냈다.** 기록해 둔다 —
이 기록이 없으면 다음 사람이 같은 순서로 밟는다.

1. **판정을 출력 문자열로 했다.** 변이는 실제로 red를 냈는데 `tail -1`이 요약 줄이 아니라
   short summary의 마지막 줄을 집어 **"초록"으로 읽었다.** ⇒ **종료 코드로 판정한다.**
   (곁가지로: `addopts`의 `-q`와 하네스의 `-q`가 겹쳐 `-qq`가 되면서 요약 줄 자체가
   사라져 있었다 — "몇 건이 죽었나"를 못 적고 있었다.)
2. **잔여 확인을 `git status`로 했다.** 커밋 안 된 다른 작업이 **변이 잔여로 오인**됐다.
   ⇒ **백업과 파일 단위로 대조한다.**
3. **stale `.pyc`에 속았다.** 소스는 복구됐는데 `__pycache__`가 남아 테스트가 옛 코드를 보고
   red를 유지했고, 그것이 **"복구 실패"로 읽혔다.** 다음 변이는 기준선이 red라 중단됐다.
   ⇒ `PYTHONDONTWRITEBYTECODE=1` + 복구 시 `__pycache__` 제거.

**교훈**: ⑤(초록 복귀)와 ⑥(잔여 없음)이 있었기 때문에 이 셋이 전부 드러났다.
**변이가 red를 냈는지만 보는 하네스였다면 셋 다 통과했을 것이다.**
