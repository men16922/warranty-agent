# 비용 가드레일 (운영 규약)

> spec이 아니다. **지켜야 할 습관**이다. 근거는 성질이 아니라 **전례**다.

---

## 1. 강제 규칙

1. **크레딧을 먼저 받는다** — 못 받으면 범위를 줄이지, 자비로 메우지 않는다. ✅ 08-19 완료.
2. **teardown 날짜를 제출과 동시에 박는다** — **2026-09-02**. 캘린더 등록(T8-6).
3. **상시 과금 컴퓨트 금지** — ⛔ GKE · ⛔ 상시 VM · ⛔ Cloud SQL (REQ-705, D8).
4. **전용 프로젝트** — teardown이 프로젝트 삭제 하나로 끝나게(D9).
5. **주 2회 지출 점검** — 단, ⚠️ **점검 자체가 과금**이다. 일 단위 조회로(#6), 매일 안 한다.

## 2. overnight 하네스 permission boundary

무인 루프가 **배포하거나 과금하면 안 된다.** DENY가 ALLOW를 이긴다.

**deny 목록에 반드시 넣을 것:**
```
   gcloud *            bq *              gsutil *
   make deploy         make live-check   make demo (라이브 경로)
   terraform *         docker push
```
**allow는 게이트 타깃만:**
```
   make check          pytest            ruff        mypy
```

⚠️ **`Bash(make *)` 같은 포괄 allow를 절대 넣지 않는다.** 그러면 `make deploy`가 통과한다.

## 3. 알려진 함정 (레퍼런스 전례)

| 함정 | 무엇이 일어났나 | 이 프로젝트의 대응 |
|---|---|---|
| **잊힌 컴퓨트** | 클러스터를 방치해 청구 | scale-to-zero만 · teardown 날짜 고정 |
| **정지해도 청구** | 정지 인스턴스가 내내 있었는데 "0대"로 세고 있었다 (실행 중인 것만 셌다) | 전용 프로젝트 → 프로젝트 삭제로 종결 |
| **MTD가 "지금"이 아니다** | 월 누계의 82%가 이미 멈춘 리소스의 과거 누적 (**15배 왜곡**) | 일 단위 조회 |
| **측정이 최대 지출** | 비용 조회 API가 며칠간 그날의 최대 항목 | 화해 일 1회 · **파티션 필터 필수** · 자기 비용을 원장에 기록(REQ-406) |
| **크레딧이 $0으로 보이게 한다** | 크레딧 상쇄로 기본 조회가 $0 반환 | `cost`와 `credits`를 **둘 다** 읽는다(REQ-402) |
| **게이트가 과금** | 테스트마다 모델 호출 → 288초 | REQ-701 + 가드 G5 |
